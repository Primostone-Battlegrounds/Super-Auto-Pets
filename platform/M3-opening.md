# 千星兼容目录开场结算

八席原生战斗开场复用同一份宠物目录、Lua 战斗算式及原生商店的 Park–Miller 随机流。每次处理一个原始槽位，双方同槽按种子决定先后。开始时固定原始出战身份，之后按当前站位选目标。离场的动物跳过，召唤物移入队列后的阵容。一次技能的多随机目标按顺序在未选目标中抽取。扣血、护盾、退场、前排增益和召唤顺序可由 Lua 回放复验。

`gstsServerOpeningState` 接收尚未开场的战斗板和种子，返回独立的开场状态表。用 `gstsServerOpeningStep` 驱动该状态和战斗板，结束后战斗板直接进入共用的冲撞内核。`nativeBattle` 为双人和八席宿主生成共享节点图源码、编号顺序、开场及退场元数据。默认兼容目录，也可选 `release`。六阶样本覆盖前排打击、后排打击、退场护盾和新增召唤物。受击、溅射及召唤增益的原生时序仍在接入。

从仓库根目录执行隔离编译、读回及 Lua 对照。输出包含读回的 GIL 路径、节点预算、种子样本结果和证据摘要。

```sh
MILIASTRA_ALLOW_LIVE_WRITE=0 node tests/native/verify-m3-opening.mjs \
  /tmp/miliastra-mcp /tmp/m3-opening-validation lua5.3 lua5.4 /tmp/m3-opening-probe
cd /tmp/m3-opening-probe
sha256sum -c SHA256SUMS
```

离线模拟逐项比对开场先手、事件及全部有效阵容。样本包含空阵、低血量、护盾、同批退场、移动后的起手槽位、召唤插队、正负整数种子边界、固定种子重放及回合交换站位。复验官方图引擎时，用隔离 GIL 的日志对照包内 `evidence.json` 的 `probeEvents`。兼容样本种子为 `1922112213`，六阶样本种子为 `13`，实际值记录在 `probeSeed`。

在上述验证命令末尾追加 `release` 并更换候选目录，可以构建六阶开场样本。源码对照额外核对有新增护盾、召唤物的完整交战。将开场和退场元数据设为图变量初值；六阶退场表有 115 个字段，超过节点单次组装列表的 100 个参数上限。
