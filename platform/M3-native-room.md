# 千星八席完整对局候选

`m3-release-room.gil` 使用六阶首发目录，包含相邻喂食、先手、受伤、出击、退场与召唤联动。`m3-compatibility-room.gil` 使用项目现有三阶兼容目录。关卡为 1 至 8 名真人连接。首次发现玩家后默认等待 5 秒，满八位立即锁定，并在服务端补足逻辑机器人。每个席位持有独立商店。真人和机器人共用原生经营指令、成长与战斗节点。机器人从空阵容购买、成长、喂食和刷新。四阶以后，机器人可出售未升级的旧种，并优先补入新种。准备收尾时按 Lua 入门策略的三组攻命权重选择前排，并通过共用调位指令实施。

关卡图负责席位、身份、序列、经营、准备锁定、配对、结算、排名和冠军。战斗图每个调度步推进一组的开场技能或一次碰撞。两个图通过关卡内部请求与回执传递单步工作，并校验阶段、轮次、批次和当前关卡身份。胜负、平局、人数奇数轮空、准备超时、主动离开与弃赛都有离线模拟。战斗双方获得相同的帧，自然结算时获得同一组锁定阵容、战斗种子与结果。客户端用共享 Lua 战斗规则重算可单步浏览的回放并校验结果。离线用两版 Lua 逐场比对原生终局棋盘。

关卡图以开局时锁定的平台玩家实体绑定席位。原实体临时缺席时保留席位，超出恢复窗口后按弃赛处理。原实体返回可用「同步」恢复私有商店、当前阶段及名次。当席位在本轮已完成实战时，同步也会重新发送该场权威回放。补发范围截止在下一轮开场，轮空与弃赛结算不生成实战回放。官方客户端是否保留原实体身份和是否能导入重连状态仍需实机验证。

## 构建与复验

从仓库根目录运行。最后可附整数种子、1 至 3 秒的调度间隔和 0 至 60 秒的候场等待，默认分别为 1、1 秒和 5 秒。建包使用项目固定工具、Lua 5.3 和 Lua 5.4。构建使用隔离夹具并检查原文件没有变化。

```sh
sh platform/setup-tools.sh /tmp/m3-room-miliastra-mcp
MILIASTRA_ALLOW_LIVE_WRITE=0 node tests/native/verify-m3-room.mjs \
  /tmp/m3-room-miliastra-mcp /tmp/m3-native-validation lua5.3 /tmp/m3-compatibility-room 1 1 5
cd /tmp/m3-compatibility-room
sha256sum -c SHA256SUMS
```

六阶候选从仓库根目录执行同一命令，将输出目录换为 `/tmp/m3-release-room`，末尾添加 `--release`。默认种子的八种人数配置均须到达第六阶，且每种配置都要完成含新增动物的实战。回归逐场比较人机与机器人互战的权威棋盘。

`--headless` 可生成服务端结构样本供节点调试。验收使用带界面的默认产物。证据记录 Lua 版本、实际 GIL 哈希、两张原生图的挂载、静态预算、定向信号和读取的客户端脚本。源码模拟完整执行关卡与战斗图的信号交互和全部真人数，记录运行时间、内存、调度次数、消息数和每步调用峰值。方法调用数属于离线模拟，平台实际耗时另测。

## 官方客户端最小验收

1. 核对下载包 SHA-256。使用获授权的隔离存档导入，同一关卡先在 PC 单人试玩。进入后确认真人 1 与机器人 7。买宠、合并或喂食，冻结商品并刷新、准备、观察自动对战、触发轮空、玩到唯一冠军。六阶候选在第 11 轮开放第六阶，记录高阶动物或相邻喂食的表现。保留首轮入席、第一场结算、回放和终局证据。
2. 官方「多人试玩」用两台设备，各提交一次不同购买、一次重复和一次准备。核对两人的金币、准备锁定、对手与生命，检查同场收到的顺序帧及落败扣血。手机实测点按、阵容选择和按键命中，PC 实测鼠标输入、快捷键与回放。
3. 另开两人局，一名真人在战斗结算期间暂时离线，并在同轮内返回后点「同步」。记录平台实体是否保持、当前商店、轮次、名次和恢复的权威回放。若平台为恢复者创建新实体，检查其未获得旧席私有商店和回放。另一局确认认输或退出试玩，核对弃赛名次、剩余对局继续及官方「重新挑战」能否开始新局。
4. 验证官方好友准备区是否允许在 1 人和 2 人时按最低人数开局。条件允许时用八名真人验证满员立即入席、各店独立和官方负载。记录帧时、定时偏差、结算耗时和是否出现服务器负载提示。
