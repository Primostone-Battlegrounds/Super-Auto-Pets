# 千星八席完整对局兼容候选

`m3-compatibility-room.gil` 使用项目现有三阶兼容目录。关卡为 1 至 8 名真人连接；首次发现玩家后默认等待 5 秒，满八位立即锁定，并在服务端补足逻辑机器人。每个席位持有独立商店。真人和机器人共用原生经营指令及战斗节点。机器人从空阵容购买、成长、喂食和刷新，使用本候选的轻量策略。六阶追加技能与完整策略仍需在原生多人环境继续验证。

关卡图负责席位、身份、序列、经营、准备锁定、配对、结算、排名和冠军。战斗图每个调度步推进一组的开场技能或一次碰撞。两个图通过关卡内部请求与回执传递单步工作，并校验阶段、轮次、批次和当前关卡身份。胜负、平局、人数奇数轮空、准备超时、主动离开与弃赛都有离线模拟。战斗双方获得相同的帧，自然结算时获得同一组锁定阵容、战斗种子与结果。客户端用共享 Lua 战斗规则重算可单步浏览的回放并校验结果。离线用两版 Lua 逐场比对原生终局棋盘。同一实体临时缺席会保留席位并允许恢复当前经营态。平台能否在断线后保留实体身份、官方客户端上行来源及重载后的回放保留仍需实机验证。

## 构建与复验

从仓库根目录运行。最后可附整数种子、1 至 3 秒的调度间隔和 0 至 60 秒的候场等待，默认分别为 1、1 秒和 5 秒。建包使用项目固定工具、Lua 5.3 和 Lua 5.4。构建使用隔离夹具并检查原文件没有变化。

```sh
sh platform/setup-tools.sh /tmp/m3-room-miliastra-mcp
MILIASTRA_ALLOW_LIVE_WRITE=0 node tests/native/verify-m3-room.mjs \
  /tmp/m3-room-miliastra-mcp /tmp/m3-native-validation lua5.3 /tmp/m3-compatibility-room 1 1 5
cd /tmp/m3-compatibility-room
sha256sum -c SHA256SUMS
```

`--headless` 可生成服务端结构样本供节点调试。验收使用带界面的默认产物。证据记录 Lua 版本、实际 GIL 哈希、两张原生图的挂载、静态预算、定向信号和读取的客户端脚本。源码模拟完整执行关卡与战斗图的信号交互和全部真人数，记录运行时间、内存、调度次数、消息数和每步调用峰值。方法调用数属于离线模拟，平台实际耗时另测。

## 官方客户端最小验收

1. 核对下载包 SHA-256。使用获授权的隔离存档导入，同一关卡先在 PC 单人试玩。进入后确认真人 1 与机器人 7。买宠、合并或喂食，冻结商品并刷新、准备、观察自动对战、触发轮空、玩到唯一冠军。记录首轮入席、第一场结算、终局和收到的对手动画。
2. 官方「多人试玩」用两台设备，各提交一次不同购买、一次重复和一次准备。核对两人的金币、准备锁定、对手与生命，检查同场收到的顺序帧及落败扣血。手机实测点按、阵容选择和按键命中，PC 实测鼠标输入、快捷键与回放。
3. 另开两人局，一名真人暂时离线后返回。记录平台事件来源、原席是否恢复和当前商店可见性。再次开局后由另一人确认中途退出，检查名次和余下席位继续。如平台会为恢复者创建新实体，核对旧席私有状态只由原授权实体获得。
4. 验证官方好友准备区是否允许在 1 人和 2 人时按最低人数开局。条件允许时用八名真人验证满员立即入席、各店独立和官方负载。记录帧时、定时偏差、结算耗时和是否出现服务器负载提示。
