# 千星双人同步候选

该隔离关卡用于验证好友 1v1 所需的玩家身份和回合信号。两人各自准备后，服务端结算一轮，两人各自确认后开启第二轮。第二次结算结束验证。关卡只显示同步状态。

屏幕中的刷新、准备和下一轮按钮通过客户端 Lua 发送操作与回合。下方四个圆形交互按钮在玩家模板图上触发，节点图用平台提供的按钮编号选出操作和固定回合，再通过同一个关卡节点图处理。两条路径都由关卡图核对信号来源是否为在场玩家。原生按钮用数字键 1 至 4 测试，手机触控需要实机确认。[客户端信号说明](https://github.com/FurinyaWorks/genshin-miliastra-mcp/blob/59c576e41632a6bf6781bbca83a676d0da0374ec/knowledge/notes/client-lua.zh-CN.md) · [原生交互按钮实测](https://github.com/FurinyaWorks/genshin-miliastra-mcp/blob/59c576e41632a6bf6781bbca83a676d0da0374ec/examples/buttons/WALKTHROUGH.md)

## 构建和检查

从仓库根目录使用固定版 MCP 与 Lua 5.3 构建。

```sh
sh platform/setup-tools.sh /tmp/auto-pets-miliastra-mcp
MILIASTRA_ALLOW_LIVE_WRITE=0 node tests/native/verify-m2-probe.mjs \
  /tmp/auto-pets-miliastra-mcp /tmp/auto-pets-native-validation lua5.3 \
  /tmp/m2-duel-probe
cd /tmp/m2-duel-probe
sha256sum -c SHA256SUMS
```

CI 的 `m2-duel-probe-<SHA>` 产物含 `m2-duel-probe.gil`、校验文件和读回证据。GIL 使用 2/2 人设置。验证读回四个原生按钮、玩家图和关卡图的挂载与信号连接，并在模拟中分别执行两条输入路径。M1 单人候选另行保留。

## 双设备验收

1. 导入获授权的隔离存档，通过系统菜单的「多人试玩」上传该测试存档并邀请另一名真人。双方进入准备区，待下载完成后由房主开局。账号需达到奇匠 Lv.2，以便显示自定义文字。记录客户端版本、关卡和 GIL SHA-256。[千星官方多人试玩说明](https://github.com/FurinyaWorks/genshin-miliastra-mcp/blob/59c576e41632a6bf6781bbca83a676d0da0374ec/knowledge/official/guide/mh9fj3rudd9q.md)
2. 先测原生路径。订阅 `_GSTS_AP_DuelProbe`、`_GSTS_AP_DuelButtons` 和客户端脚本日志。两人入场后，各按一次 `1` 刷新。两台设备应显示不同席位、同一第 1 轮和 0 次结算。玩家图应打印两次 `AUTO_PETS_M2 native_input`，对应不同玩家编号。
3. A 按两次 `2`，应显示等待对手。B 按一次 `2`，两台设备应显示第 1 轮、结算 1 次。两人按 `3` 进入第 2 轮。再按 `2`，准备状态应维持原样。交换顺序，各按 `4` 并重复一次。两台设备最终应显示第 2 轮、结算 2 次、验证完成，关卡图每轮各有一次 `settled`。手机可尝试点按对应圆形按钮，单独记录结果。
4. 另开一局测试 Lua 路径。用面板上的「刷新状态」「准备」「下一轮」重跑两轮，核对双方快照版本和两次结算。分别保留两条路径的两端截图和日志。若点击后收到 `AUTO_PETS_M2 missing_player_source`，保留该次输入及原始日志。关卡图会拒绝缺少可核对来源的操作。开场时 Lua 会自动发一次刷新，判断原生路径时用玩家图按键日志对应本次输入。
