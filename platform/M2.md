# 千星双人同步候选

该隔离关卡用于验证好友 1v1 所需的玩家身份和回合信号。两人各自准备后，服务端结算一轮，两人各自确认后开启第二轮。第二次结算结束验证。关卡只显示同步状态。

## 构建和检查

从仓库根目录使用固定版 MCP 与 Lua 5.3 构建。

```sh
sh platform/setup-tools.sh /tmp/auto-pets-miliastra-mcp
MILIASTRA_ALLOW_LIVE_WRITE=0 node tests/native/verify-m2-probe.mjs \
  /tmp/auto-pets-miliastra-mcp /tmp/auto-pets-native-validation lua5.3 \
  /tmp/m2-duel-probe
cd /tmp/m2-duel-probe
sha256sum -c SHA256SUMS
```

CI 的 `m2-duel-probe-<SHA>` 产物含 `m2-duel-probe.gil`、校验文件和读回证据。GIL 使用 2/2 人设置，M1 单人候选另行保留。

## 双设备验收

1. 在获授权的千星多人测试环境导入此 GIL，用两台设备加入同一隔离关卡。账号需达到奇匠 Lv.2，以便显示自定义文字。记录客户端版本、关卡和 GIL SHA-256。编辑器单人试玩无法验这一项。[千星客户端实测记录](https://github.com/FurinyaWorks/genshin-miliastra-mcp/blob/59c576e41632a6bf6781bbca83a676d0da0374ec/knowledge/notes/client-lua.zh-CN.md)
2. 打开关卡节点图 `_GSTS_AP_DuelProbe` 和客户端脚本日志。两人入场后，各点一次「刷新状态」。两台设备应显示不同席位、同一第 1 轮和 0 次结算。
3. 由 A 点两次「准备」。A 显示等待对手，B 仍可准备。B 点「准备」后，两台设备都显示第 1 轮、结算 1 次。双方的日志应有相同快照版本，且节点图只有一次第 1 轮的 `settled`。
4. 两人点「下一轮」，确认进入第 2 轮。交换准备顺序并多次点击，两台设备最终都应显示第 2 轮、结算 2 次、验证完成。保留两端截图和日志。
5. 若节点图出现 `AUTO_PETS_M2 missing_player_source`，记录客户端版本和原始日志。该事件缺少可与在场玩家核对的来源，服务端会拒绝该操作。
