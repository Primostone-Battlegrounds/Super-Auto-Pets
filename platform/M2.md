# 千星双人商店候选

两位玩家在各自的三格货架购买动物。关卡图按在场玩家身份扣金币、清除已购货位、把动物加入该玩家的五格阵容，并只发送其本人商店。两人完成购买并准备后，关卡记录一次同步结算。确认进轮会换货并补金币，保留阵容。第二次同步结算结束验证。

两轮货架、价格、初始金币和动物属性由现有 Lua 名册与双人商店用固定种子导出。候选运行的是购买、准备锁定与回合推进。原生自动战斗、合成和刷新仍待接入。

客户端 Lua 发送操作和当前回合。下方圆形按钮走玩家模板图，每个购买键绑定固定轮次和货位。两条路径共用同一个关卡图，验证来源和购买合法性。手机点按需要官方实机确认。[客户端信号说明](https://github.com/FurinyaWorks/genshin-miliastra-mcp/blob/59c576e41632a6bf6781bbca83a676d0da0374ec/knowledge/notes/client-lua.zh-CN.md) · [原生交互按钮实测](https://github.com/FurinyaWorks/genshin-miliastra-mcp/blob/59c576e41632a6bf6781bbca83a676d0da0374ec/examples/buttons/WALKTHROUGH.md)

## 构建和检查

从仓库根目录使用固定版 MCP 构建。货架由 Lua 5.3 和 5.4 各导出一次并核对。

```sh
sh platform/setup-tools.sh /tmp/auto-pets-miliastra-mcp
MILIASTRA_ALLOW_LIVE_WRITE=0 node tests/native/verify-m2-probe.mjs \
  /tmp/auto-pets-miliastra-mcp /tmp/auto-pets-native-validation lua5.3 \
  /tmp/m2-duel-probe
cd /tmp/m2-duel-probe
sha256sum -c SHA256SUMS
```

CI 的 `m2-duel-probe-<SHA>` 产物含 `m2-duel-probe.gil`、校验文件和读回证据。验证读回 2/2 人设置、原生按钮、图挂载和定向商店信号，并分别模拟两条路径的购买和两轮准备。

## 双设备验收

1. 导入获授权的隔离存档，通过系统菜单的「多人试玩」上传该测试存档并邀请另一名真人。双方进入准备区，待下载完成后由房主开局。账号需达到奇匠 Lv.2，以便显示自定义文字。记录客户端版本、关卡和 GIL SHA-256。[千星官方多人试玩说明](https://github.com/FurinyaWorks/genshin-miliastra-mcp/blob/59c576e41632a6bf6781bbca83a676d0da0374ec/knowledge/official/guide/mh9fj3rudd9q.md)
2. 先测原生路径。两人各按 `1` 刷新并记录第 1 轮各自的货架和 10 金。A 连按两次 `5` 买一号货位，预期变为 7 金、一号货位售罄、阵容新增一只，B 的货架及金币原样。B 用 `6` 买二号货位。分别保留玩家图的 `AUTO_PETS_M2 native_input` 和两端的 `AUTO_PETS_M2 market` 日志。
3. A 按 `2` 准备，再按 `6` 试买，已准备席位的金币应保持原样。B 按 `2` 后两端应见第 1 轮结算一次。双方按 `3` 进入第 2 轮，核对金币恢复至 10、货架换新及旧队员保留。按 `5` 试旧轮指令，再用 `8`、`9` 或 `0` 买新货位。各按 `4` 准备，重复一次后总计仍为两次结算。手机点按圆形按钮的结果单独记录。
4. 另开一局，使用面板上的货架、刷新、准备和下一轮重跑 Lua 路径。记录两端商店版本、金币、阵容和结算。若收到 `AUTO_PETS_M2 missing_player_source`，保留对应点击和原始日志。开场时 Lua 会自动发一次刷新，判断原生路径时以玩家图的按键日志对应本次输入。
