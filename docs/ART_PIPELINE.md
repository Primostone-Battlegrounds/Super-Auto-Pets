# 原生动物美术工艺

首批交付为赤团雀、水晶宴、鬼兜虫、棘冠鳄四只千星原生样板。后续候选为珊瑚蝶和野林猪。各动物的官方参考定位、主要识别点与技能见 [参照矩阵](REFERENCE_MATRIX.md)。

## 工艺来源与预算

采用《杀戮原塔2》已获视觉认可的大色面、图元预算、共享定义和逐实例验证方法。该项目的锚点为简单造型 **44 个绘图控件／41 个图元**，复杂造型 **119 个绘图控件／115 个图元**。36／110 是辨识度过低的对照。首批四只从 44 个绘图控件内起稿。需要更复杂的造型时，先在同档移走次要细节、补足主轮廓，仍不合格再提交对照和超档理由。119 档是复杂造型评审参照，设备容量由本项目实测确定。[源工艺](https://github.com/FurinyaWorks/Slay-the-Heavens/blob/73c21489efaab409d4c0c46bee517d410d3427fc/docs/art/NATIVE_MONSTER_PRODUCTION.md)

绘图控件计入实际创建的椭圆、矩形、三角、容器及分页。镜像后的实际控件和拼接出来的每个三角均按实际行计数。血量、等级、状态和交互等 HUD 另外记录。验收分别记录每张样板的绘图控件、每个完整实例的控件和实际同屏峰值。

## 单只样板

1. **固定官方参考。** 从参照矩阵打开图鉴条目或游戏内对应画面，记录链接或条目位置、来源版本和所用视角；选出 1–3 个在最小尺寸还能识别的特征。依照官方动物的剪影、色彩和材料辨识来设计本项目的原生构图、比例与姿态。运行时使用项目自己的图元造型。
2. **先轮廓，后细节。** 用大色面和少量明暗层定体型。椭圆保曲面，矩形定直边，三角补角、鳍或棘冠。共用适合复用的局部定义，保留有方向性的眼、喙、角和体纹。优先通过父容器做位移与受击反馈。
3. **同尺寸图审。** 在相同底色、锚点和显示比例下并列官方参考、上一轮和本轮。约 127 px 用于与原工艺对照，实际通过条件以商店卡位、五格编队和战斗 HUD 的最小显示尺寸为准。遮住物种名，检查四只是否能凭剪影或主色区分，并保留关键特征、预算与取舍记录。
4. **输出可实例化定义。** 同种动物以物种定义查找图元模板。每只活体有独立的控件实例、位置与朝向、血量、命中、状态、受击和退场反馈。在计数报告中记录图元行、容器数与实际创建量。静止姿态运行 120 次更新，确认无逐图元写入和重建。继续验证隐藏回访后复用、解绑后完整释放、退出后活跃控件归零。[逐实例工艺](https://github.com/FurinyaWorks/Slay-the-Heavens/blob/73c21489efaab409d4c0c46bee517d410d3427fc/docs/art/MULTI_MONSTER_DRAWINGS.md)

## 千星原生接入

- 接在 TASK-3 的隔离 Lua/GIL 入口和 TASK-8 的界面路径。把同一绘图定义用于商店、队伍和战斗表示。生成并导入候选后读回模板注册与索引、布局绑定及实例关联。回归要走实际入口并核对日志和控件，而非只展示预览截图。
- 以启用名册与实际同屏实例容量估算绘图池。在五格对五格及实际 UI 共存场景实测峰值，覆盖同种多只、首现、换位、受击、阵亡/清理、召唤适用路径、重复开局、分配失败和部分创建后的释放。失败时清理已分配控件并产生可定位日志。
- 同一候选分别记录离线创建与释放、千星导入读回、PC 和手机实机证据。在两端核对最小显示尺寸、战斗层序、点击或触控、受击表现、同种实例独立及退出清理，附候选提交、工具或客户端版本、场景、截图或日志及峰值。按 [QA 分层](QA.md) 记录。
