## Evidence authority

Code inspection establishes that a path exists, not that it works on a physical device. Tests establish only their stated harness/simulator behavior. HTML fixture captures establish only that study. A successful official run must identify device/client, exact GIL hash and source SHA. No category may be promoted into another by wording.

The HTML's five identical recruit cards, invented creatures, explicit Adjust/Cancel mode, fixed victory, six-event fixture and three-round finish are study limitations. They are not the full v2 release contract or proof of parity with native implementation. The intended inventory follows approved catalog/tier rules; do not replace production food/reward slots with five identical illustrative pets simply to match the study. Multiplayer-specific inventory differences require an explicit rules/layout mapping and independent review.

## Documented adaptations and review decisions

- **Miliastra invitations/lobbies:** native service and room authority replace any source service interface. Review supported pending/error/retry/leave behavior, not a cloned invitation UI.
- **Touch/native inspection:** separate read-only Inspect is justified because a touch device cannot rely on hover and source/target taps already perform actions. Keep the existing purchase/feed/reorder actions; do not silently repurpose their targets.
- **Practice:** standalone local AI and explicit difficulty fit this project's approved scope. Do not label a fixed HTML victory as that AI.
- **Playback:** preserve observed causal clarity and familiar playback roles. Native cursor controls may differ where constrained, with action mapping disclosed. Exact source milliseconds are not available from a promotional montage; distinguish approved project timing from source measurement.
- **Original visuals/content:** use original/licensed assets and approved catalog, while retaining usable information priority. Promotional media is research, never runtime art.

Independent review must assess these choices, the complete intended screen/state coverage and deviations, and the truthful implementation map. It can approve the design as an implementation basis while official checks remain pending; that does not certify present code, activate a manifest, or permit release.
