# Interactive local study

Serve this directory over HTTP and open `index.html` in a browser. For example: `python3 -m http.server 8765 --directory docs/design/revisions/v2.0.0/prototype`. This is a local deterministic study, not the Miliastra game or multiplayer simulator.

Automated smoke/scenario verification: `node docs/design/revisions/v2.0.0/prototype/verify-prototype.cjs`. Requires installed `playwright` and `/usr/bin/chromium`; uses a random loopback HTTP port and closes it at completion. Screenshots default to `/tmp/sap-prototype-evidence`; set `SAP_PROTOTYPE_EVIDENCE` to retain an independent evidence set. The test also verifies front identity, first attack highlight and actual DOM geometry so both fronts face the center. Screens update without whole-screen fade on selection or battle ticks. The test checks actual buttons and rendered state, including invite-before-start, direct and target-slot purchasing, reordered team, currency, freeze across refresh/round, battle speed/skip/result, end/restart, and sell. It checks horizontal overflow and Ready position in the 844×390 viewport. No account or internet access is needed for interactions; optional webfont falls back to the system font.

Read `../SPECIFICATION.md`, `../INTERACTIONS.md` and `../ACCEPTANCE.md` before interpreting captures. In particular, fixed victories, three-round completion, illustrative abilities and simulated invitations are deliberately labeled fixtures. Production/source-reuse gates remain open. An actual device playthrough and platform simulator cannot be replaced by this browser test.

The complete intended design and current native snapshot are mapped in `../IMPLEMENTATION-MAP.md`. This study is not the canonical full shop inventory or source interaction parity target. Its explicit Adjust mode, five identical recruit offers and fixed battle differ from the native drag/source-target actions, separate pet/food/reward inventory and real engine/replay paths. Independent design-basis approval may proceed with those boundaries and physical runs pending; it does not change Proposed status or product NO-GO.
