# 架构

`src/autopets/` 保存纯 Lua 领域逻辑。目录提供模板和规则常量。商店持有持续阵容、货架和回合边界。战斗消费两个独立的前到后队伍快照及显式种子，产生可回放的结果和事件。单局控制器编排阶段、胜场和失败次数。

本地 AI 使用独立种子从空队开始。策略读取自身商店快照，提交玩家共用的商店命令。训练对局消费同轮快照，结算与进轮复用玩家规则。回放检查初始空队、命令、边界、战斗和状态摘要。

`autopets.duel` 为两个席位分别持有商店和生命。宿主传入已验证的玩家身份和单调毫秒时钟，按回合和席位序号接收操作。准备截止或双方锁定后，服务端复用同一战斗实例结算双方。两人确认或结算超时后开下一轮。每人的快照只带自己的商店和双方共用的已结算回放。

当前 1v1 规则候选可由宿主设置准备与结算时限、起始生命及房间总时限。默认 60 秒准备、10 秒结算、5 条命，败方扣 1 命，平局保留生命。房间默认 45 分钟到期，按剩余命数判胜，同命为平局。千星运行时的身份、输入及回合同步由独立候选验证。[双人候选](../platform/M2.md)

`autopets.room` 管理八人淘汰赛的八个逻辑席位。首位真人入座后默认等 5 秒，满席提前开局，期限到达时由机器人填满空席。宿主可以配置等待、准备、结算和整局时限。活动席位拥有独立商店和生命。机器人从空阵容开始，使用单人 AI 的策略向同样的商店接口提交指令。`autopets.versus` 负责双人及八人模式共同的身份、轮次、请求序号、准备和商店操作校验。

八席每轮使用固定种子配对。奇数存活时轮空，优先给此前轮空次数最少的席位。同场对战双方收到相同的回放，败方扣 1 命，平局与轮空保命。每轮统一处理淘汰，退出会立即确定该席名次。剩最后一席时获胜。默认满 40 轮或 45 分钟时，按剩余生命、胜场和种子派生的席位顺序确定剩余名次。

宿主通过 `join` 提供已验证身份，用单调毫秒 `tick` 推进时限。`request` 使用与 1v1 相同的回合、序号和动作字段。`public_snapshot` 只包含席位、存活、生命、对手和排名等公开信息。`snapshot` 额外返回该身份的商店与该席的回放。`leave` 代表明确退出。若宿主收到相同身份的恢复连接，可以请求该席当前快照。真实连接生命周期和平台房间能力需要单独验收。

千星 UI 把输入转换为领域指令，从快照和事件渲染。暂停、步进、跳过和菜单均由表现层管理。终端入口和 GIL 读回路径共享领域源码。

具体签名、状态所有权与验收分层见 [REASONS v1](design/REASONS-v1.md)。
