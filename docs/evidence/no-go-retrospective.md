# 真机 NO-GO 整改与复验

工作项 TASK-41。原交付基线 `ab73443adee5a2b5b37268779356c2fe67220886`，本轮设计候选 `v2.0.0`。用户要求先用 Simulator 打稳基础。以下复现来自该基线的源码、GIL、实际 Simulator 和历史 PR。原始设备材料仍待归档。

| 缺陷 | 已复现原因与漏检机制 | 日常入口与反例 |
| --- | --- | --- |
| 标题、状态、属性和八席排名的文字消失 | 原 GIL 控件已绑定，但字高、行距与控件高度组合可得零绘制行。主菜单标题需要 67.8 单位，原高度 61。旧离线图根据布局数据自行排字，读回检查只比较名称、类型和尺寸。 | 正式 GIL 比较文字内容、字号、对齐、缩放和输入标志。Beyond Simulator 用回读控件测可见行并保存 PNG。冻结基线复现零行。最小探针区分静态、动态、Latin、CJK 和自适应字号。官方权限和字库单列待验。 |
| 好友等待、提前开八席和未准备操作无反馈 | 主菜单首个房间信号前读取未初始化人数。拒绝响应原先只包含当前人数。以前的脚本先注入房间状态再点按钮，并按已知的布局路径调用事件。 | 在无响应时测试首次点按、超时、重试、服务器拒绝、到齐和补位。客户端显示请求中与拒绝原因。服务器仍按在场身份确认模式。双人和八席空阵容准备、认输确认、返回都有回归。 |
| Simulator 首轮结束后无法继续 | 实际 Lua VM 缺 `string.pack`，且整数为 32 位。旧规则测试使用桌面 Lua，离线客户端验证使用自行实现的控件适配。 | 实际 Simulator 从回读的 GIL 运行原 Lua，回放完整 15 轮。规则同时测试整数拆分与训练摘要的兼容路径，保留原轨迹字节序和随机序列。 |
| 原版参照表无法证明还原度 | 来源跨多个原版版本，宣传静态图没有当前客户端构建或触控、邀请、时序轨迹。旧 PR 的原版复验也记录了同版轨迹缺口。 | 设计清单分别记来源版本与核实状态。现有两个官方图的用途和哈希已固定，运行尝试和访问失败按轨迹记录。原版流程验收等待同版输入、录像时间戳与独立对照。 |
| CI 和独立评审未覆盖官方平台 | 旧评审检查了源码、节点图、隔离 GIL 与离线画布，也明确标注官方 PC、手机、好友、断线和重挑战待验。统一下载链接让读者难以看到交付状态。 | GIL 包标定同一候选身份，`ACCEPTANCE.json` 分开记录五层及三个官方场景。候选包可用于隔离试玩。只有同候选的证据齐全、设计已激活，`--require-go` 才能通过。 |
| 背景、原生 HUD 与平台操作 | 软件画布能验证自定义背景、控件尺寸和命中，官方 HUD、返回键、触控安全区、房间邀请由客户端实际渲染和调度。 | 统一界面独立全屏背景与安全区内交互，读回核对鼠标及按键拦截标志。官方双端需要录制房间到关卡、结算到退出的连续轨迹，核验 HUD、文本权限和输入冲突。 |

历史记录可追溯至 [PR #47 独立复验](https://github.com/Primostone-Battlegrounds/Super-Auto-Pets/pull/47) 与 [PR #50 原生列表容量修复](https://github.com/Primostone-Battlegrounds/Super-Auto-Pets/pull/50)。

## 执行顺序

1. Backlog 和 PR 都填同一 `Design-Version`。PR 填 `Work-Item`。CI 从 PR 精确头提交读取设计，并用目标 SHA 检查版本迁移及冻结内容。唯一入口为 [manifest.json](../design/manifest.json)。
2. 在候选干净工作树跑两版 Lua 规则。固定 MCP 构建并读回统一 GIL。校验 `SHA256SUMS`。实际 Beyond Simulator 加载回读的 Lua 与布局。候选验证记录 1、2、8 个客户端会话。多人服务器逻辑的节点图验证单独记录。
3. 由未参与对应实现的人核对实际运行图与逐步输入。记录候选 SHA、GIL SHA-256、设计指纹、画布、关键字段可见性和缺陷。Slay-the-Heavens 的原生读回与实际 Simulator 分层做法已移植。旧画面或原型报告可以追溯历史，验收读取当前候选的证据。
4. 用授权隔离的官方 Windows PC、手机和千星好友房间完成实际验收。MCP 有 `playtest_start`、`playtest_status`、`playtest_frames`，可安排输入、截图和原生日志并抽帧。连续录像、手机和真实多设备协调需要对应设备与采集能力。
5. 运行 `node scripts/acceptance-gate.mjs <包目录> --require-go` 取得成品状态。合并依据包括当前提交的 Project checks、独立评审和设计版本状态。当前 GitHub develop API 返回空的分支规则，仓库工作流负责检查，集成者负责执行合并条件。
